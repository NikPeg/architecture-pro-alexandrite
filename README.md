# Architecture Pro: Александрит

Проект содержит архитектурные решения для компании "Александрит" — производителя ювелирных украшений на заказ. Система представляет собой распределённую микросервисную архитектуру с тремя основными приложениями: онлайн-магазин, CRM и MES (система управления производством).

## О проекте

Компания "Александрит" столкнулась с серьёзными проблемами производительности и надёжности после открытия API для внешних продавцов. Проект включает пять архитектурных решений, направленных на повышение наблюдаемости, отказоустойчивости и производительности системы.

### Архитектура системы

- **Онлайн-магазин** (Vue + Java Spring Boot) — для клиентов B2C
- **CRM** (Vue + Java Spring Boot) — для продавцов
- **MES** (React + C#) — для операторов производства
- **Базы данных**: PostgreSQL (Shop DB, MES DB)
- **Хранилище**: S3 для 3D-файлов
- **Очереди**: RabbitMQ для интеграции между системами

### [Task 5: Архитектурное решение по кешированию](./Task5/Архитектурное%20решение%20по%20кешированию.md)

**Описание:** Решение по внедрению кеширования для повышения производительности системы, особенно для MES. Включает:
- Анализ элементов системы для кеширования
- Выбор типа кеширования (серверное vs клиентское)
- Выбор паттерна кеширования (Cache-Aside)
- Диаграммы последовательности операций
- Стратегия инвалидации кеша (по ключу, временная, программная)
- Сравнение различных решений
- Техническая реализация (C#, Java)

**Технологии:**
- Redis для серверного кеширования
- Паттерн Cache-Aside для операций чтения
- Комбинированная стратегия инвалидации

**Основные цели:**
- Ускорение загрузки списка заказов в MES (с 2-5 секунд до < 200 мс)
- Снижение нагрузки на базы данных на 70-80%
- Повышение продуктивности операторов на 40-50%

## Основные проблемы, решаемые проектом

1. **Потеря заказов** — решается через трейсинг и логирование
2. **Медленная работа MES** — решается через кеширование и оптимизацию
3. **Отсутствие наблюдаемости** — решается через мониторинг, трейсинг и логирование
4. **Высокая нагрузка на БД** — решается через кеширование
5. **Сложность диагностики проблем** — решается через логирование и трейсинг

## Технологический стек

- **Мониторинг:** Prometheus, Grafana
- **Трейсинг:** OpenTelemetry, Jaeger
- **Логирование:** ELK Stack (Elasticsearch, Logstash, Kibana)
- **Кеширование:** Redis
- **Инфраструктура:** Kubernetes, Docker, Yandex Cloud
- **Языки:** Java (Spring Boot), C#, Vue.js, React, TypeScript

## Результаты внедрения

### Технические метрики:
- **Response Time:** улучшение в 10-25 раз для кешированных запросов
- **MTTD (Mean Time To Detect):** с 2-4 часов до < 5 минут
- **MTTR (Mean Time To Resolve):** с 4-8 часов до < 30 минут
- **Cache Hit Rate:** > 80%
- **Нагрузка на БД:** снижение на 70-80%

### Бизнес-метрики:
- **Продуктивность операторов:** увеличение на 40-50%
- **Удовлетворённость клиентов:** увеличение на 20-30%
- **Количество жалоб:** снижение на 30-80%
- **Order Completion Rate:** увеличение до 99.9%
